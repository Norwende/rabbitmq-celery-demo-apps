Infrastructure OrderFlow installée dans le namespace {{ .Release.Namespace }} (release {{ .Release.Name }}).

RabbitMQ ({{ .Values.rabbitmq.replicas }} nœuds, géré par l'opérateur) : l'opérateur crée StatefulSet/rabbitmq-server
et Secret/rabbitmq-default-user. --wait ne suit pas ce StatefulSet ; attendre explicitement :
  kubectl -n {{ .Release.Namespace }} wait --for=condition=AllReplicasReady rabbitmqcluster/rabbitmq --timeout=600s

Interface de management :
  kubectl -n {{ .Release.Namespace }} get secret rabbitmq-default-user -o jsonpath='{.data.username}'   # base64
  kubectl -n {{ .Release.Namespace }} get secret rabbitmq-default-user -o jsonpath='{.data.password}'   # base64
  kubectl -n {{ .Release.Namespace }} port-forward svc/rabbitmq 15672:15672   # puis http://localhost:15672

Redis Sentinel ({{ .Values.redis.replicas }} pods, master "{{ .Values.redis.masterName }}") :
  kubectl -n {{ .Release.Namespace }} exec redis-0 -c sentinel -- redis-cli --no-auth-warning -p 26379 SENTINEL get-master-addr-by-name {{ .Values.redis.masterName }}
Mot de passe : Secret/{{ include "orderflow-infra.redis.secretName" . }} (clé "password"){{ if not .Values.redis.auth.existingSecret }}, généré au premier install et conservé aux upgrades{{ end }}.

Étape suivante : les applications (chart orderflow)
  helm upgrade --install orderflow charts/orderflow -n {{ .Release.Namespace }} --wait
  (ou ./scripts/deploy-apps.ps1, qui construit aussi les images)
